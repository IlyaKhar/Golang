# Руководство по деплою

## ТЕОРИЯ: Деплой (Deployment) приложений

### ЧТО ТАКОЕ ДЕПЛОЙ:
Деплой - это процесс размещения приложения на сервере, чтобы оно было доступно пользователям через интернет.

### ЗАЧЕМ НУЖЕН ДЕПЛОЙ:
1. Приложение должно работать 24/7 (не на твоём компьютере)
2. Пользователи должны иметь доступ через интернет
3. Нужен стабильный сервер с хорошим uptime
4. Автоматическое масштабирование при нагрузке

### ПЛАТФОРМЫ ДЛЯ ДЕПЛОЯ:
1. **Render.com** - современная платформа, простая настройка
2. **Heroku** - популярная платформа, много документации
3. **AWS, GCP, Azure** - облачные провайдеры (более сложные)
4. **DigitalOcean, Vultr** - VPS серверы (нужно самому настраивать)

---

## 1. ПОДГОТОВКА ПРИЛОЖЕНИЯ К ДЕПЛОЮ

### ТЕОРИЯ: Перед деплоем нужно подготовить приложение
- Настроить переменные окружения
- Убедиться что порт читается из переменной окружения
- Настроить логирование
- Подготовить Dockerfile (опционально)

### КЛЮЧЕВЫЕ МОМЕНТЫ:
1. **Порт должен читаться из PORT** (платформы сами назначают порт)
2. **Не хардкодить конфигурацию** (использовать env переменные)
3. **Логи должны идти в stdout/stderr** (платформы читают оттуда)
4. **Graceful shutdown** для корректного завершения

## 2. RENDER.COM

### ТЕОРИЯ: Render - современная платформа для деплоя
- Простая настройка через веб-интерфейс
- Автоматический деплой из GitHub
- Бесплатный тариф для начала
- Поддержка Docker и обычных приложений

### ПРЕИМУЩЕСТВА:
- Автоматический деплой при push в GitHub
- SSL сертификаты автоматически
- Логи в реальном времени
- Переменные окружения через веб-интерфейс

### НЕДОСТАТКИ:
- Бесплатный тариф "засыпает" после 15 минут бездействия
- Ограничения на бесплатном тарифе

### КАК ДЕПЛОИТЬ:
1. Зарегистрируйся на https://render.com
2. Нажми "New +" -> "Web Service"
3. Подключи GitHub репозиторий
4. Настрой:
   - Name: golang-app
   - Environment: Go
   - Build Command: `go build -o server ./deploy`
   - Start Command: `./server`
5. Добавь переменные окружения:
   - PORT: 8080 (или оставь пустым, Render сам назначит)
   - DATABASE_URL: (если используешь БД)
   - JWT_SECRET: (если используешь JWT)
6. Нажми "Create Web Service"
7. Render автоматически задеплоит приложение
8. После деплоя получишь URL: https://golang-app.onrender.com

## 3. HEROKU

### ТЕОРИЯ: Heroku - популярная платформа для деплоя
- Много документации и примеров
- Простой CLI для управления
- Add-ons для БД, Redis и т.д.
- Автоматический деплой из GitHub

### ПРЕИМУЩЕСТВА:
- Огромная экосистема add-ons
- Хорошая документация
- CLI инструменты
- Поддержка многих языков

### НЕДОСТАТКИ:
- Бесплатный тариф отменён (только платные тарифы)
- Дороже чем Render для простых приложений

### КАК ДЕПЛОИТЬ:
1. Установи Heroku CLI: https://devcenter.heroku.com/articles/heroku-cli
2. Зарегистрируйся на https://heroku.com
3. Войди через CLI: `heroku login`
4. Создай приложение: `heroku create golang-app`
5. Настрой переменные:
   ```bash
   heroku config:set DATABASE_URL=...
   heroku config:set JWT_SECRET=...
   ```
6. Деплой: `git push heroku main`
7. Открой приложение: `heroku open`

---

## 4. ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ

### ТЕОРИЯ: Переменные окружения - способ хранения конфигурации
- **Не храни секреты в коде!**
- Используй переменные окружения для конфигурации
- Платформы позволяют настраивать env переменные через веб-интерфейс

### ЧТО ХРАНИТЬ В ENV:
- `DATABASE_URL` - строка подключения к БД
- `PORT` - порт сервера
- `JWT_SECRET` - секретный ключ для JWT
- `API_KEY` - ключи для внешних API
- `ENVIRONMENT` - окружение (development, production)

## 5. DOCKER ДЛЯ ДЕПЛОЯ

### ТЕОРИЯ: Docker - контейнеризация приложений
- Упаковывает приложение и зависимости в контейнер
- Работает одинаково на любой платформе
- Можно деплоить на любую платформу с поддержкой Docker

### ПРЕИМУЩЕСТВА:
- Изоляция зависимостей
- Одинаковая работа на любой платформе
- Легко масштабировать
- Можно деплоить на любую платформу (Render, Heroku, AWS, etc.)

---

## КЛЮЧЕВЫЕ ПРАВИЛА ДЕПЛОЯ

1. ✅ **ВСЕГДА читай PORT из переменной окружения**
2. ✅ **НИКОГДА не хардкоди секреты в коде**
3. ✅ **Используй graceful shutdown для корректного завершения**
4. ✅ **Логи должны идти в stdout/stderr**
5. ✅ **Тестируй локально перед деплоем**
6. ✅ **Используй переменные окружения для конфигурации**
7. ✅ **Настрой автоматический деплой из GitHub**
